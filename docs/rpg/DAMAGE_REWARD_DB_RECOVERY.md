# 전투 피해 처리·재화 곡선 DB 복원 (2026-10-27)

작업 브랜치: `restore/rpg-damage-reward-db`. 원본 바이너리와 추출 DB를 기준으로 복원했으며, 전체 원본 전투/경제 서버 복원 완료를 뜻하지 않는다. 공개 저장소에는 복원 도구·테스트·범위 문서만 둔다. 원본 DB와 네이티브 바이너리는 커밋하지 않는다.

## 피해 처리

원본 RunEffect 순서: 명중/회피 → 최종 공격력 → 치명타 → 초치명타 → 최종 피해 → HP/보호막 정산 → 보호막 폭발 → 사망·후처리 → 그로기 게이지 감소.

| 구성 | 이번 상태 | 한계 |
|---|---|---|
| 최종 피해 | 기존 48개 능력치·일반/보스 보정·방어율 순차 적용 유지 | 활성 효과 디스패처 전체는 미복원 |
| 치명타/초치명타 | 별도 확률 굴림, 치명타 저항, DB 상한, 플래그 복원 | RNG와 상한은 호출자가 명시; 초치명타 활성 효과의 라이프사이클은 별도 |
| 피해 정산 | 보호막, 무적/우회, 피해 1 제한, 초과 피해, HP 0 제한 | 개별 보호막 레이어 소진 순서는 미검증 |
| 패시브 호출 순서 | 보호막 파괴 15 → HP 변경 12 → 사망 11 | 이벤트 효과 자체는 자동 실행하지 않음 |
| 그로기 | 치명타/물리/마법/기본/스킬 감소량 가산 분리 | 그로기 상태 전이 전체와 활성 효과 연결은 후속 |
| 웹 전투 | 플레이어/몬스터/대체 몬스터 공격의 HP·보호막 정산 공통화 | 기존 공격력·성장 밸런스와 테스트 HP 10,000 유지 |

보호막 추가 피해율은 직관적인 `1+bonus/100` 역산과 다르다. 양수 bonus일 때 원본은 보호막 소비량을 `float32(100/bonus+1)`로 나눈 값을 HP 피해에서 차감한다. 예: 피해 100, bonus 50, 보호막 200 → 보호막 150 소모, HP 50 감소. 원본과 다르게 단순화하지 않는다.

원본 ARM64 차등 검증은 수식 본문을 실행하며 객체 조회·수치 디코더·RNG 등 주변 의존성은 명시된 테스트 픽스처다. 실제 게임 서버 실행 검증과 구분한다.

- 최종 피해 3,980건 / 회복 405건: 기존 검증 유지
- 피해 정산 3,456건: HP·보호막·플래그·이벤트 순서 대조
- 치명타/초치명타 1,200건: 수치와 난수 소비 횟수 대조

## 재화·성장 DB

`vardian-reference.sqlite`: 원본 58개 테이블의 손실 없는 JSON 왕복, 능력치·장비·성장식·조건·참조 관계를 정규화. 원본 metadata SHA 일치 시에만 10개 enum의 109개 상수를 교정한다.

`vardian-rewards.sqlite`: 재화 획득 경로를 별도 조회할 수 있도록 구성한다.

| 항목 | 건수 |
|---|---:|
| 재화 종류 | 94 |
| 챕터별 기본값 (10종 × 1,200챕터) | 12,000 |
| 스테이지 (모든 모드) | 7,717 |
| 스테이지 보상 그룹 | 30,868 |
| 개별 보상 정의 | 110,954 |
| 챕터 진행 보상 | 1,200 |
| 사냥 이벤트 | 9 |

주요 골드 기본값: 챕터 1 = 300, 10 = 600, 100 = 9,777, 500 = 31,993,634, 1,200 = 11,162,225,642,645. 이는 **챕터 기본 계수**이며 몬스터 한 마리당 또는 방치 보상 1회당 지급액으로 단정하지 않는다. EXP·숙련·의지·크리스탈·소울젬·마나스톤·각인·비전·Umbra도 원본 벡터를 모두 보존한다.

방치 주기 120,000ms / 최대 86,400,000ms / 보너스 최대 3회·7,200,000ms. 시간상 최대 720틱이지만 틱마다 기본값을 그대로 지급한다는 근거는 아직 없다.

보상 수량은 SQLite TEXT + Python Decimal로 보존한다. 원본 MaxCount=0과 누락값은 서로 다르다. 현재 웹의 1e12 상한은 후반부 원본 골드 기본값을 자르므로, 이번에 원본 곡선을 웹 지갑에 무조건 적용하지 않는다.

## 사용

```bash
# 원본 decoded 폴더와 metadata-enums.json이 있는 소스에서 생성
npm run rpg:restore:rewards -- --source /private/export/decoded --output /private/reward-db
npm run rpg:rewards -- --db /private/reward-db/vardian-rewards.sqlite --chapter 100
npm run rpg:rewards -- --db /private/reward-db/vardian-rewards.sqlite --category Labyrinth --stage 1
npm run rpg:restore:db -- --source /private/export --output /private/full-db --enum-corrections docs/rpg/recovered-combat-enums.json
npm run test:rpg:reference
npm run test:rpg
npm run check:rpg
```

조회 도구는 읽기 전용이며 SQL 매개변수를 사용한다. 확정 수량 GiveAll·재화 보상만 `static_material_quote`로 계산 가능하다. PickEach/PickNTimes 확률, 복원 미확정 Chance 의미, RefIdleCurChapter 배수, 장비 뽑기, 보상 그룹별 이벤트 라우팅은 임의 해석하지 않고 명시적으로 거부한다.

## 남은 원본 자료/연결

1. 보호막 폭발 901·CC 후처리·패시브 재진입을 포함한 활성 효과 상태 머신.
2. 누락 ActionData 2016/2036/2056/2430의 원본 레코드.
3. 덮어쓰기 없는 원본 map_scenes 번들: 웨이브·NPC 참조 및 좌표 확정.
4. 서버 보상 선택/배수·방치 지급식 근거. 정적 표는 복원했지만 서버 권한 지급·중복 방지 정책은 별도 설계/검증 대상.
5. 웹 저장 지갑의 대형 수량 표현과 기존 저장 데이터 마이그레이션.

확인되지 않은 보상·스킬을 0 또는 임의 값으로 채워서 '완전 복원'으로 표시하지 않는다. 이번 작업은 별도 복원 브랜치에서 검토하며 운영 배포는 하지 않는다.
