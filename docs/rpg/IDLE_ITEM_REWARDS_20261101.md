# 실제 컬렉션·아이템 보상·시드 변경 (2026-11-01)

이번 아이템 API와 보관함은 공용 `game.sqlite`의 `rpg_players.progress`에서 실제 `gemCollection`과 장비 인스턴스를 읽는다. 보유 젬은 장착 중인 수량을 포함하며, 초월 여부가 젬 수량을 늘리지 않는다. 실사용 `/api/rpg/items` 요청은 `gameStorage.progress.load → initializeIdleProfile → 변경 시 CAS save → 아이템 작업`을 같은 `sqliteAtomic` 트랜잭션에서 처리한다. 실패하면 초기화·방치 시간 갱신·아이템 소비/지급 모두 롤백한다. 초기 스타터 젬/장비/영혼석을 반복 조회로 다시 지급하지 않는다.

기존 독립 `RpgItemsStore` 테스트에서만, 해당 계정의 `rpg_players` 행 자체가 없으면 기존 테스트 컬렉션을 유지한다. 프로필이 존재하는 계정을 올 컬렉션으로 취급하지 않는다. UI에는 올 컬렉션/무한 보유 표시를 제거하고 실제 종류 수·복사본 수·보유 무기를 표시한다. 초월은 실제 보유 젬 또는 실제 장비 인벤토리에 있는 무기 종류만 허용한다. 이전 초월 결과와 최초 초월석5개 정책은 보존한다.

## 자체 웹 보상 규칙

이 비율은 복원된 바르디안 원본 확률/경제 수치가 아니라 명시적인 웹 버전 설정이다.

| 서버가 확인한 사건 | 지급 |
|---|---|
| 사람 플레이어의 실제 순이익 캐시 게임 승리 | 마일리지10 |
| 위 승리의 족보가 플러시 이상 | 시드 변경권1 추가 |
| UTC 월요일 기준 주간10승 도달 | 초월석1, 해당 주1회 |
| 서버 단계별 보스 첫 처치 | 초월석1, 계정/단계당1회 |
| 기존 서버 토너먼트 플레이어1위 | 기존 초월석1 정책 유지 |
| 마일리지100 교환 | 비스타터 젬1개 또는 시드 변경권1개 선택 |

현금이나 유료 상품 결제는 이 경로에 추가하지 않았다. 캐시 보상 메서드는 서버 내부의 `awardCashWin(eventId, account, {flushPlus})`이며 아이템 HTTP API에서 호출할 수 없다. 포커 서버가 실제 사람·순이익 승리·족보를 확인해야 한다. `awardBossFirst(account,stage)`도 서버 내부에서 실제 살아 있던 보스가 죽은 전이를 확인한 후 호출한다. 메서드는 같은 사건 ID의 재시도에 재지급하지 않는다. 주간 초월석은 주별 별도 고유 사건 ID를 사용하여 서버 시각이 앞뒤로 변해도 같은 주의 초월석을 다시 지급하지 않는다.

마일리지 젬 교환은 액티브45%/보조55%, 해당 종류 안의 후보는 동일 확률이다. 기본6액티브는 후보에서 제외한다. 보유 중인 비스타터 젬이 다시 나오면 수량+1이다. 서버 crypto 난수만 사용하고 클라이언트가 보낸 젬 ID/난수는 받지 않는다. 이 교환은 실제 소환 비용/소환 횟수/영혼석에 영향을 주지 않으며, `gemCollection`과 플레이어 revision을 CAS로 갱신한다.

## 시드 변경과 저장

`rerollJewel(account,instanceId,requestId,revision)`은 보유 중인 Timeless 주얼만 허용한다. 공용 DB에 저장된 빌드의 장착 목록을 같은 트랜잭션에서 검사하고, 장착 중이면 먼저 해제하도록 거부한다. 변경권1개를 소비하며 현재 시드와 다른1~10000의9999개 결과에서 동일 확률로 새 시드를 선택한다. 주얼 종류·인스턴스 ID·Conqueror는 유지한다.

아이템 revision 검증으로 오래된 보관함의 동시 소비를 거부하고, 요청 영수증은 action/대상에 묶는다. 동일 요청 재전송은 다시 난수를 뽑거나 소비하지 않으며 동일 요청 ID로 다른 대상을 보내면 거부한다. 주얼 시드 변경, 변경권 소비, revision 갱신, 영수증·사건 기록은 한 트랜잭션이다. 마일리지 교환도 지급·차감·플레이어 CAS·영수증이 한 트랜잭션이다.

새 테이블 `rpg_item_rewards`와 `rpg_item_requests`를 사용한다. 기존 `rpg_items` 열 구조를 바꾸지 않아 이전 파일의 `INSERT ... SELECT *` 이전과 충돌하지 않는다. 프로세스 사이의 지급/소비는 SQLite `BEGIN IMMEDIATE`와 고유 키로 직렬화한다. 보존 기간은 실제 DB 파일/배포 스토리지 설정에 달려 있으며, 임시 디스크를 영구 저장으로 표현하지 않는다.

## 검증

`test-idle-items.ts`의10개 테스트는 실제 컬렉션/장비 소유권, 초월 대상과 재시도 묶음, 캐시·주간·보스 보상 중복, 실제 지갑 정산 콜백 뒤 SQL 실패의 전체 롤백, 장착/타인/비Timeless 변경 거부, 시드/변경권/CAS/영수증 롤백, 마일리지 젬 지급과 플레이어 CAS 롤백, 두 프로세스의 변경권1개 경합, 실제 Next API 초기화와 실패한 작업의 프로필 롤백을 검사한다.10개 모두 통과했다. 기존 아이템/주얼 상점 테스트9개와 RPG TypeScript 검사도 통과했다.

형식 모델은 추가하지 않았다. 기존 공유 SQLite 트랜잭션 구현에 대한 실제 SQL 결함 주입·별도 프로세스 경합·API 통합 검증을 우선했으며, 검사 범위를 넘어 모든 오류 부재를 주장하지 않는다.
