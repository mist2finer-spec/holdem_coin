# 옴브라 공용 트리 · 올 컬렉션 젬 · 초월 시험 구현

## 적용 범위

`/hunt`의 기본 촛불 미궁 로그라이크에 적용. 원본 게임/PoE의 완전한 밸런스 복원이 아닌 웹 프로토타입이다. 업로드한 `PoE_스킬젬_직업별정리.pdf`, `PoE_패시브노드_직업별정리.pdf`를 분류 참고로 사용했다. 소환·토템 계열은 제외한다. Astra 최고 추론 에이전트가 이번 작업의 순수 트리/젬 코어를 구현하고 검토했다. 주 에이전트는 전투·저장·토너먼트·UI를 통합했다.

## 트리와 시작점

- 52개 기존 도끼 노드 ID와 수치 유지 + 8개 영역의 19개 노드 + 영역 간 연결로 18개 = **222개**. 9개 캐릭터 시작점이 연결된 하나의 무방향 그래프다.
- 홍은 도끼 근접 시작점 `root`. 다른 캐릭터는 기동/연격/투사체/정밀/수호/원소/비전/균형 영역에 대응한다. 다른 캐릭터의 전투 선택 제한은 이전 점프 테스트 정책을 유지한다. 영역 보기 선택은 카메라만 이동하며 시작점을 바꾸지 않는다. 서버는 홍이 다른 캐릭터 시작점으로 바꾸는 요청을 거절한다.
- 기본12P + 레벨 보너스, 최대51P. 연결된 노드만 배울 수 있고 회수로 연결을 끊을 수 없다. 홍→카오스 면역 최단 경로는12P. 범위 노드는 기존처럼 실제 거리와 표시 반경에 적용.
- 증가 합산, 증폭 곱산; 반경=`sqrt(면적 배율)`. 근접/주문/투사체/물리/원소/혼돈 피해, 생명력, 마나, 보호막, 치명타, 흡수, 지속 피해, 막기, 억제, 기동 등에 실제 효과를 연결했다.
- CI: 최대 생명력1, 혼돈 피해 면역, 기본 최대 생명력에 비례한 에너지 보호막. 일반 피해는 보호막부터 소모, 혼돈 피해는 보호막을 우회하되 CI가 있으면0. 마지막 피해4초 뒤 보호막이 초당20% 회복. 일반 HP/보호막 수치는 Decimal로 유지. 구성 변경 시 기존 유효체력 비율을 유지해 재할당으로 무료 전회복하지 않는다.

## 젬

- **35개 액티브 / 30개 보조**. `build-catalog.ts`에 설명·태그·수치, `hunt-build.ts`에 검증·컴파일. 액티브6칸 × 보조5칸 = 슬롯별 최대6링크. 같은 보조 중복 연결 금지. 액티브 교체 시 태그 불일치 보조만 해제하며 보관함에서 잃지 않는다.
- 근접, 투사체, 원소 주문, 혼돈/지속 피해, 회복, 가드, 오라, 자동 시전 계열을 우선 구현. 바르디안의 기존6개 모션/VFX 계열을 재사용하며, 35종의 전용 신규 원화나 원작의 모든 개별 젬을 복원한 것은 아니다.
- 주기 발동, 직접 타격 치명타 후 발동, 실제 피격 후 발동. AUTO OFF에서도 조건이 맞으면 작동한다. 마나·기존 스킬 쿨타임·최소 발동 간격을 모두 지킨다. 발동 보조는 링크당1개; 이미 자동 발동인 스킬·채널·특정 오라와 충돌하는 연결은 금지한다. 발동된 타격/반복/DoT는 또 다른 치명타 발동을 만들지 않는다. 짧은 사건 유효창을 넘어선 오래된 피격/치명타는 뒤늦게 발동시키지 않는다.
- 투사체 수+연쇄+관통은 같은 적을 중복으로 맞추지 않는 최대 표적 수로 우선 구현했다. 실제 비행 궤적·물리 충돌은 향후 단계다. 지속 피해는0.5초 분할 틱, 가드/오라는 기존 타격과 함께 적용한다. 여러 오라는 현재 마지막 시전 효과를 사용한다.
- 테스트 보관함의 액티브/보조는 전부 무제한 보유. 가방의 별도 젬 탭에서 확인하고 젬·코어에서 연결한다. 사냥/싱글 홀덤6·8인/서버 홀덤의 무작위 젬 드롭은 **향후 경로**로 표시만 했으며, 이번 올 컬렉션 테스트에서는 무작위 획득을 켜지 않았다.

## 골드 성장

- `무기 · 성장 → 성장 · 골드 능력치`에서 기존 공격/체력 수련을 구매한다. 복원된 기존 `buyArt(101/102)` 비용/능력치 구조를 재사용한다. 공격 수련은 기본 공격과 스킬 피해, 체력 수련은 기존 테스트HP 정책에 맞춘 받는 피해 감소에 반영한다. 기본10,000HP는 유지하되 생명력 노드와 CI는 별도로 적용한다.
- 이번 탐험의 실제 처치 골드(일반10/보스100)를 게스트 저장 골드에 함께 반영한다. `awardHuntKill`의 EXP/레벨 곡선·마스터리·스킬 사본 획득 경로를 재사용하되, 이 호출의 골드/영혼석 보상은0으로 덮어 이중 지급하지 않는다. 계정 처치 수도 한 번만 증가한다. 레벨이 오르면 포인트가 증가한다.
- 레거시 캠페인도 확장 컴파일러를 사용하지만 CI/트리거/투사체 등 추가 메커니즘의 주 검증·구현 대상은 기본 RogueEngine이다. Unity의 기존 BigDouble/면적 계산은 유지했으며 이번 확장 메커니즘을 Unity Editor까지 포팅·검증했다고 주장하지 않는다. 내보내기 JSON에는 새 분류와 시작점·범위를 포함한다.

## 초월과 토너먼트 연동

- 처음 보관함 생성 시 테스트용 초월석5개. 액티브/보조 젬 ID와 무기4종별로1회만 초월. 현재 로그라이크 장착 무기는 도끼이며 다른 무기의 결과는 보관만 된다.
- 결과는 각25%: 증폭(피해×1.2/마나×1.2), 확장(면적×1.3/피해×.95/마나×1.1), 순수(피해×1.12), 안정(변화 없음). 아이템당1회·되돌리기 불가. 장착 젬·도끼의 결과는 다음 시전부터 적용한다. 기본 공격에도 도끼 초월 적용.
- 8인 서버 토너먼트의 실제 최종 정산에서, 플레이어가 유일한 생존 우승자일 때 **초월석1개**. CPU 우승/관전자/단순 클라이언트 우승 주장은 지급 경로가 없다.
- 웹에서 현재 HTTP-only RPG 게스트에 대해32바이트 무작위 연결 키를 만들고 Socket JOIN 시 전달한다. 최초 좌석 배정에만 묶으며 재접속 이름 변경·다른 키로 상품 수취인을 바꾸지 않는다. 클라이언트는 연결 키를 얻을 때까지 최대3회 재시도하고 실패하면 토너먼트에 입장하지 않는다. 연결에 실패했던 좌석도 후발 키로 가로챌 수 없다. 시작 전 퇴장한 좌석은 해제한다. 같은 브라우저의 같은 RPG 게스트가 필요하다.
- `items.sqlite` WAL 트랜잭션 + 대회UUID의 UNIQUE 이벤트로 프로세스 재시도/다른 연결에서도 중복 지급 방지. 초월은 요청UUID 재전송 캐시 + wallet revision 검사 + 차감/결과/이벤트 단일 트랜잭션. 틀린 revision은 재추첨·차감하지 않는다. 저장 실패 시 다음 토너먼트 상태 조회에서 보상을 재시도한다.
- `start-hosted.mjs`가 웹과 포커에 동일한 절대 `RPG_SAVE_DIR`을 전달한다. 대회 진행상태와 아직 지급 전인 우승 결과는 기존처럼 메모리에 있어 프로세스가 유실되면 미지급 보상의 재복구까지 보장하지 않는다. 지급 완료 이벤트의 중복 방지만 SQLite로 보장한다. 현재 Render의 기존 디스크/플랜을 변경하지 않았다. 영구 디스크가 없는 배포의 게스트 SQLite는 재배포·재시작 때 보존을 보장하지 않는다. 운영 경제로 전환하기 전에 영구 저장과 계정 인증을 마련해야 한다.

## 검증

기존 실제 엔진/SQLite 테스트를 우선. 그래프 경로, 태그 조합, 발동 조건, 극대 HP, 원자적 상품/소모를 실제 코드에서 검사했다. 새 형식 모델은 만들지 않았다: 변경한 동기 처리/트랜잭션을 직접 통합 테스트할 수 있고 기존 수학/경로 불변 조건은 전수 입력 검사로 확인 가능했다. 제한된 테스트가 전체 게임 안전성 증명은 아니다.

검사 명령: `npm run check:rpg`, `npm run test:rpg:build`, `npm run test:rpg:rogue`, `npm run test:rpg`, 포커 서버 `npm test`, `npm run build`. 새 코어 검사는9개 시작점×222개 경로 및35×30 태그쌍을 검사한다. 새 토너먼트 검사는 실제 `finishHand` 정산→우승→동일 게스트 초월석6개(초기5+보상1)→재시도에도6개를 확인한다.

릴리스 전 결과: RPG 타입 검사/프로덕션 빌드 통과. 빌드·젬·아이템36개, 로그라이크47개, 기존 RPG135개, 포커245개 = **463개 테스트 통과**. 기존 .NET BigDouble 러너를 명시적 경로로 실행해 기존 피해/면적/정산 **50개 교차언어 벡터**도 통과했다(지수 일치, 가수 허용오차1e-12). 새 CI/트리거/투사체 메커니즘의 Unity 동등성을 검증한 결과는 아니다.

별도 두 Node 서버 프로세스를 동시에 실행하는 경합 검사도 통과: 동일 대회 이벤트1건만 지급, 같은 wallet revision의 서로 다른 초월 요청은1건만 승인. 금액뿐 아니라 XP/처치 수도 같은 시퀀스 재전송 시 중복 증가하지 않음을 확인했다. 참조 PDF와 화면 캡처는 외부 업로드 자동 승인에서 제외되어 Git에 포함하지 않았다.

## 운영 화면 확인

- 실제 `/hunt`에서 홍으로 입장. `화염구 + 주기적 시전 + 다중 투사체 + 연쇄 + 영감 + 원소 집중` 6링크 저장을 확인했다. 타격 배율0.58, 투사체3+연쇄2, 기본 면적 배율1.00. AUTO OFF에서 버튼을 누르지 않은 상태로 다시 쿨타임6초가 표시되어 조건부 자동 시전이 지속됨을 확인했다.
- 사냥 EXP로 기본12P에서13P가 되었고, 도끼 범위1 습득 후12/13P로 차감. 범위 면적+12%, 재사용−2% 표시를 확인했다.
- 보유990G에서 공격 수련150G 구매→840G, 공격 수련Lv.1, 다음 비용152G. 사냥 실재화/기존 비용곡선 연결을 화면에서 확인했다.
- 화염구 초월석 사용5→4, `안정` 결과 저장·동일 대상 버튼 비활성 확인. 안정은 의도된25% 무변화 결과다. 증폭/확장/순수의 실제 배율은 엔진 테스트로 별도 확인했다.
- 실제 운영 토너먼트 전체를 플레이하여 우승한 것은 아니다. 보상 경로는 실제 서버 정산 함수와 두 프로세스 경합 통합 테스트로 검증했다.
- 중간 배포 교체 중 기존 전투 세션이 만료되는 기존 메모리 세션 정책을 확인했다. 새로 입장해 최종 버전에서 검증했다. 장기 영구 저장 보장은 위 저장 제한을 참조한다.


최종 운영 런타임: `dc6dbab0a38d9df6a8a183fb4803d0c7509f7257`, Render `dep-dbjblnrbc2fs73dai43g` LIVE. `main`과 `feat/rpg-expanded-builds` 모두 푸시. 최종 레이아웃에서 젬 보관함의 긴 목록 스크롤·닫기·액티브35/보조30·초월석5 초기 표시를 재확인했다. `/api/release`가 런타임 SHA와 일치하고 `/healthz`가 web=true,poker=true임을 확인했다.


자료 업로드 제한: 자동 승인 검토가 참조 PDF/화면 캡처의 GitHub 게시를 차단했다. 운영 코드는 이미 배포됐고, 이 기록과 프로세스 경합 테스트만 Git에 추가한다. 원본 자료의 외부 게시를 재시도하지 않았다.
