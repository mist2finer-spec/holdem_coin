# 장비 소켓과 공통 전투 컴파일러 (2026-11-01)

이 문서는 `POE_780_JEWELS_20261101.md`의 최초 구현 이후 변경된 전투 규칙을 기록한다. 780 정적 노드, 기존 노드 ID/연결, 군주얼 구조와 Timeless 변환은 유지한다. PoE 원본 엔진의 복제나 모든 오류 부재를 의미하지 않는다.

## 실제 장비 그룹

`BuildState` v2에 선택 필드 `equipment`를 추가했다. 운영 서버는 소유 검증을 마친 `HuntProgress.equipment`를 이 필드에 복사한다. 장비가 있는 빌드의 스킬은 `weapon / armor / gloves / boots / ring1 / ring2`에 장착된 **각 아이템의** `gems`만 읽는다. 첫 소켓은 액티브, 나머지는 그 액티브를 보조하는 보조 젬이다. 아이템을 교체하면 해당 아이템의 소켓 내용도 함께 바뀐다. 빈 액티브 소켓은 시전/자동 시전/마나 소비를 허용하지 않는다.

장비 없는 저장을 읽는 이전 API의 계산은 호환성을 위해 남겼다. 운영 마이그레이션 후에는 보관된 `links`/`activeIds`가 추가 링크를 제공하지 않는다. 기존 6×5 링크 배열을 삭제하거나 새 장비 용량에 맞춰 잘라 저장하지 않는다. 소유 젬 수량 검증과 마이그레이션 지급은 서버 저장 계층의 책임이다.

최대 물리 소켓은 검4, 도끼6, 창6, 쌍수3, 갑옷6, 장갑4, 장화4, 반지 각각1이다. 쌍수는 단일 아이템·단일 그룹이다. 등급별 용량은 `idle-equipment.ts`의 공통 표를 사용한다. 고대/신화 무기의 포악함 또는 출혈 내장 보조는 호환 태그에만 적용하며, 동일 보조 젬을 직접 꽂아도 한 번만 적용한다. 6소켓(액티브1+보조5)+내장 보조1은 7링크 상당의 효과를 만들 수 있다.

고유 갑옷의 군주얼 효과는 **실제로 할당한 군주얼 주요 노드** 한 개당 모든 피해 +15%이다. 헌신 효과는 헌신1당 공격 속도 +0.1%이며 기존 Militant Faith의 원소 피해 변환은 유지한다. 같은 고유 옵션이 여러 곳에서 중첩되는 형태는 사용하지 않는다. 이 수치와 장비 옵션의 획득 확률은 웹 게임용으로 정한 규칙이다.

## 공통 계약과 실제 효과

`compileBuild()`는 깊게 동결한 `CompiledBuild`를 반환한다. 패시브, 일반 공격, 여섯 장비 스킬, 장비/소켓 스냅샷, 독립 부여 스킬, 조건부 주얼, 시작 고유 코어와 빌린 고유 코어를 포함한다. `RogueEngine.compiledBuild`와 `HuntEngine.compiledBuild`가 같은 계약을 사용한다. 시전 중인 스킬은 시작할 때의 컴파일 결과와 쿨타임 전체 길이를 보존한다.

두 엔진은 `CombatEffects`로 오라, 발동 사건의 출처, 독립 부여 스킬 재사용과 어시스트 사건을 공유한다. 캠페인에도 실제 마나/혈마법 비용, 방어 스킬, ES, MoM, 회복, 반복, 투사체 적중 수 제한, DoT, 치명타 발동과 독립 주얼 스킬이 적용된다. 기존 캠페인과 Rogue의 기본 HP/피해·몬스터·동작 길이는 각 모드의 값이므로 원시 피해 숫자 전체가 같다는 뜻은 아니다.

오라는 `sourceId + activeId`로 독립 유지한다. 다른 오라 스킬은 동시에 효과가 있으며, 같은 오라의 여러 복사본은 가장 강한 효과 한 개만 적용한다. 실제 시전 전에는 오라가 활성화되지 않는다. 직접 Hatred와 군주얼이 부여한 Vitality가 함께 유지되는 동안 Watcher's Eye는 실제 냉기 피해 ×1.2와 초당 최대 생명력1% 재생을 모두 제공한다. 재생 불가 상태는 이 재생도 막는다.

발동 시전과 그 반복/DoT, 독립 부여 스킬의 타격은 다른 사건 발동을 일으키지 않는다. 실제 피해가 발생한 경우만 피격 사건을 만든다. 일시정지 중에는 오라/스킬/발동/재사용/마나 재생 시계가 진행되지 않는다. 부여 스킬은 `serial / skillId / sourceActor / sourceId / at` 어시스트 사건을 노출하며 기존 캐릭터 초상화 자산으로 표시할 수 있다. 새 모션을 만들지 않았다.

## 시작 고유 코어와 Forbidden

홍만 플레이 가능하다는 운영 제한은 유지한다. 나머지8개는 데이터 원형이다. 각 캐릭터의 시작 고유 코어는 `character-identities.ts`에 정의하며 자신의 시작 고유 코어는 한 번만 적용한다. 다른 시작점에 도달하는 것만으로 그 캐릭터의 고유 코어가 추가되지는 않는다.

| 캐릭터 | 시작 고유 효과 |
|---|---|
| 홍 | 근접 피해 +15%, 흡수 +1% |
| 후드 | 이동 +10%, 공격 속도 +8% |
| 백발 | 생명력 +12%, 막기 +8% |
| 금빛 | 투사체 피해 +15%, 관통 +1 |
| 정장 | 치명타 확률 +5%, 지속 피해 +15% |
| 장발 | 방어도 +20%, 보호막 효과 +15% |
| 청록 | 원소 피해 +15%, 원소 저항 +5% |
| 안경 | 주문 피해 +15%, 마나 +15% |
| 오피스 | 모든 피해 +8%, 초당 생명력 재생 +0.3% |

Forbidden Flame/Flesh 한 쌍은 `((seed - 1) % 8) + 1` 정규 시드가 같을 때 자신의 캐릭터를 제외한8개 원형 중 정확히 하나의 고유 코어를 빌린다. 보유한 1~10000 원본 시드는 변경하지 않는다. 종류별1개·한 쌍 제한은 계속 검증한다. 고정 생명력/막기 보너스만 주던 이전 규칙은 이 선택 규칙으로 대체했다.

포인트 예산은 기존 시작12를 보존한 `min(90, 12 + level - 1)`이다. 최종90포인트는 레벨79이며, 50/60포인트는 레벨39/49다. 기간과 획득 시뮬레이션은 별도의 방치 성장 문서와 도구를 따른다. 스킬 레벨·숙련·의지의 기존 저장 필드는 호환성을 위해 유지하지만 현재 방치 전투 성장에는 사용하지 않는다.

## 검증 범위

`test-equipment-combat.ts`는 실제 양쪽 엔진의 피해/HP/마나/쿨타임/오라/발동/어시스트 변화를 검사한다. 물리 소켓 상한·반지·쌍수·이전 가상 링크 차단, 내장 보조 일곱 링크와 중복 차단, 동결된 시전 스냅샷, 빈 소켓 시전 거부, 동시 오라 재생, Watcher 냉기 실제 적중 피해1.2배, Forbidden8가지 선택, 할당된 군주얼/헌신 옵션을 포함한다.

기존 1000개 prefix 그래프와 1050개 액티브/보조 조합 검증은 유지한다. 기존 테스트에서 최종 포인트 상한 기대값만51→90으로 변경했다. 회귀 테스트의 통과는 실행한 시나리오의 증거이며 모바일 모든 기기의 성능, 밸런스 완성, 운영 저장소 영구성이나 오류 부재를 보장하지 않는다.

`AGENTS.md`에 따라 기존 단위/통합/회귀 테스트를 우선했다. 이 변경의 전투 컴파일/동기 엔진은 결정적 함수와 실제 상태 전이로 검사 가능하므로 별도 TLA+/Lean/Kani 모델을 만들지 않았다.
