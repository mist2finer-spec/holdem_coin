# 원본 씬 진행 운영 연결 — 2026-10-27

## 적용 범위

원본 씬 그래프에서 지원할 수 있는 시작/영역 진입/웨이브 종료 메시지를 컴파일해 미궁 1,193개 구간(레이아웃18종)에 연결한다. 전체6,000개가 복원되었다는 의미는 아니다. NPC/컷신/독립 스포너/비활성 개체/무한 반복/불명확한 씬 등 미지원 구간은 기존 진행 어댑터를 유지한다. 현재 적용된 모든 구간의 승리 조건은 원본 KillAllMonsters(1)이다.

- `compile_scene_flow.py`: 원본 이름 해시를 StageData.MonsterInfoNameHash와 대조하고 전체 원본 MonsterDatas에서 스탯/보스 여부/스킬을 선택한다. 기존 normal/boss 두 목록으로 잘라 놓은 슬롯을 재사용하지 않는다.
- MapTheme/MapType와 MapEntityGroupId로 그룹을 선택한다. Inspector의 미리보기 선택을 쓰지 않는다. 현재 씬 이름 대조는 이전 map-assets 감사의 유일한 config 이름을 보조 근거로 사용한다. 누락된 원본 컨테이너 맵핑까지 완료했다고 주장하지 않는다.
- `hunt-scene-flow.ts`: 시작/영역 교차/지정 그룹 종료에 따른 메시지, 원본 지연 및 반복 횟수를 실행한다. waveNo를 정렬해서 순차 처치 웨이브로 만들지 않는다. 시작 메시지는 중복 시작하지 않으며, 한 프레임에 반복분을 동기 루프로 몰아 생성하지 않는다.
- 적 목록은 7개 고정 슬롯에서 유한 동적 개체 목록으로 바뀐다. 서버 스냅샷과 클라이언트 목록, 보간, 임시 스켈레톤도 함께 확장했다. 화면 밖 몬스터는 서버에서 전투를 진행하되 그리기를 생략한다.
- 원본 좌표의 주 진행축 X/Z를 웹의 300..4700으로 투영한다. 원본 3D 맵을 그대로 복원한 것이 아니다. 단일 이동선에 여러 레인이 겹칠 때 몸체가 겹치지 않도록 배치를 소폭 보정한다.
- 스폰되지 않은 영역 웨이브가 남아 있으면 적이0이어도 클리어하지 않는다. 자동 전투는 다음 진입 구역으로 이동한다. 전체 필요 웨이브가 끝나야 체크포인트/구간 보상을 한 번 지급한다.
- 저장 스키마·계정·재화 지급식·홀덤/토너먼트 로직은 변경하지 않는다. 재접속은 기존처럼 저장된 구간부터 다시 시작한다.

## 초반 구간

1-1: 소형19. 1-2: 소형18+중형3. 1-3: 소형9+중형3+대형1. 1-4: 연결된 스폰23(정의24중 한 개는 웨이브/활성화 참조가 없는 비사용 정의). 1-5: 진입 영역 활성화 후 보스1. 1-4의 지연 웨이브3개체는 시작 시 즉시 등장하지 않는다. 적용 구간에는 임의로 추가된 '일반6마리 다음 보스1마리'가 없다.

## 검증

- RPG 테스트104개 통과. 18개 적용 레이아웃 전체를 유한 종료까지 구동하고1,193개 바인딩의 스탯/이미지 참조를 확인했다.
- 자동 실제 전투로 1-1~1-5 연속 클리어, 영역 진입 전 보스 미출현, 중복 생성/보상 방지, 재접속 체크포인트를 검증했다.
- reference 테스트144개 및 RPG TypeScript 검사 통과.
- Next 운영 빌드 통과. 운영 빌드의 로컬 `/api/rpg/session`에서 stage101/적19개 응답을 확인했다.
- 개별 피해/기절/투사체 단위 테스트의 고정 fixture는 sceneFlow:false로 분리한다. 새 진행은 별도의 기본 production-mode 테스트로 검증한다.

컴파일 결과와 미지원 사유 분포는 `scene-flow-runtime-coverage.json` 참조. 원본에 남은 비활성/컷신/독립 스포너를 임의 활성화해서 전체 복원으로 위장하지 않는다.
