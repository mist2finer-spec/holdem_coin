# 세 모션 독립 타격 · S20 접속 경로 · 운영 배포 인계

기준 `4849528`, 작업 브랜치 `codex/combo-production-20261109`. 사용자가 이번에는 main 반영·배포·테스트 빌드까지 명시적으로 요청했다. 이전 인계의 '운영 미배포'는 당시 상태이며 아래 최종 검증 부록으로 갱신한다.

## 변경과 원인

- 공격1→2→3의 각 모션에 별도 attackId와 적별 hitIds를 부여한다. 콤보 전체를 한번 피해로 묶지 않는다. 같은 모션이 같은 적을 다시 스치면 중복 피해를 막고, 다음 모션은 다시 피해를 준다. 스킬은 별도 규칙이다.
- 일반 콤보 순서를 전용 카운터로 분리했다. 회피·스킬·보스 공격 serial 때문에 공격2를 건너뛰지 않는다. 기존 보스 엔진의 한 모션 전체 done 플래그도 적별 기록으로 바꿨다.
- 기존 공격2 검 끝 최저 높이는 약57cm였으므로 .31m 슬라임 위를 통과했다. 공격3은 실제로 검이 내려오는 약.61 phase 전에 활성구간(.58)이 끝났다.
- Mount에서는 원본 클립 재생 후 상완을 낮은 적 쪽으로 기울인다. 시각적인 검과 서버 접촉 프로파일을 동일한 보정으로 추출했다. 공격3의 접촉 끝을 .78로 연장했다. 원본 모델·클립·배율과 몸통/피격체 크기를 늘리지 않았다. 보스/기존 큰 슬라임은 기존 자세 프로파일을 쓴다.
- 자동 전투는 다음 모션의 실제 검 도달 범위로 적을 고르고, 너무 밀착해 닿지 않으면 간격을 확보한다. 경사면에서 헛공격만 반복하는 경우를 전체10구역 검사로 재현·보완했다. 사거리 밖은 여전히 빗나간다.
- 확인 당시 운영 `/api/release`는 `b0b822f`, `/api/rpg/mount-sunday` POST는 **404**였다. S20에서 새 구역을 로드하지 못할 수 있는 서버 원인을 확인했다. S20 자체 로그는 연결되지 않아 확보하지 못했다.
- 테스트용 localhost 주소를 PlayerPrefs에 영구 저장하던 동작을 제거했다. 기존 `island-mount-server` 키만 정리하고, 일반 재실행은 설정된 온라인 HTTPS origin으로 접속한다. 테스트 Intent를 준 실행에서만 메모리 override를 쓴다.
