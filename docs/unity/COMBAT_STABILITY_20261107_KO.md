## 계측 방법과 해석

고정 seed 111의 동일 서버 엔진을 격리된 메모리 저장소로 실행했다. 총 RTT 150ms는 각 방향 75ms로 모사했다. Editor 화면은 1080×2340, 전투 viewport는 1080×1170이며, auto 전투 후 오른쪽/위쪽 스틱을 유지한다. 25초 준비 후 60초를 기록했다. 맵 경계와 피격 중 정지가 포함되므로 CSV의 `frozenMovementFrames`는 입력 지연 지표로 사용하지 않는다.

이 환경에서는 Game View가 선택되고 프레임이 진행되어도 일반 렌더링 카운터가 대부분 0인 프레임이 있었다. 전면 표시와 Repaint만으로 해결되었다고 판단하지 않았다. 최종 전후 비교에서는 **매 프레임 전투 카메라를 명시적으로 RenderTexture로 렌더링**했다. 따라서 draw call은 추가 카메라 렌더를 포함하는 진단 수치이며 정상 Player의 단일 화면 draw call 또는 Android FPS가 아니다. GPU 시간도 이 환경에서 최종 성능 판정 근거로 사용하지 않는다. 별도의 5초 Profiler 캡처 오버헤드는 수치 비교에서 제외한다.

검증 원본은 `docs/unity/verification/combat-stability-20261107`에 보관한다. `before-rendered.csv`와 `final-rendered.csv`가 동일 조건 전후 자료다. background/focused 시도는 렌더 카운터가 대부분 0이므로 최종 GPU/FPS 검증으로 사용하지 않았다.

## 서버 유지 및 M2 후속 설계

이번 구현은 M1과 서버 판정을 유지하는 M2의 작은 수직 구현이다. 보스 전체를 C# 로컬 시뮬레이션으로 이관한 것이 아니다. 공격/회피의 실제 허용과 결과 확정에는 여전히 서버 응답이 필요하다. 서버·호스팅·플랜·DB 정책은 그대로다.

완전한 로컬 보스 전환은 20ms 고정 스텝, 프레임당 제한된 catch-up, 렌더 보간 분리, pause 복귀에서 누적 시간 폐기, 지형·AI·공격·피격·자원·규칙 버전의 TS/C# 대조가 선행되어야 한다. 계정·장비 소유·입장·정산은 현재 서버가 확정한다. 영구 보상 적용 전에 입장 ID/규칙 버전/빌드 고정/operation receipt 및 중복 정산 검증이 필요하다. 현재 보스는 영구 보상 없는 기존 훈련 모드다. 로컬 계산만으로 보안이나 동치성이 검증되었다고 주장하지 않는다.

형식 검증은 생략했다. 전투/정산 규칙과 순서·재시도 계약을 변경하지 않고 표시 캐시 및 부가 ACK를 추가했으며, 기존 서버 회귀와 실제 손실 재시도로 변경 범위를 검사했다. C# 네이티브 포팅 동치성 10만 건 검사는 이번 범위가 아니다.
