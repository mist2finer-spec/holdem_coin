## 변경 범위

마을길 10구역과 이어지는 보스, 기존 독립 Unity 보스 훈련의 이동·AI·공격·피격·회피·점프·스킬을 로컬 worker에서 실행한다. `RpgSession.Open`은 이 모드에서 더 이상 `Pump`의 반복 HTTP tick을 시작하지 않는다. 입장 응답이 실패하면 오류를 표시하며 서버 전투 경로로 몰래 되돌아가지 않는다.

새로운 C# 판정 엔진으로 다시 작성하지 않고 **현재 TypeScript MountSundayEngine과 UnityBossEngine을 같은 번들로 실행**한다. 기존 Jint worker가 엔진 상태를 단독 소유한다. 고정 스텝 20ms, 최대 배치 5스텝, 보류 시간 상한 0.5초의 기존 정책을 재사용한다. 입력 공급의 프레임 시간 상한은 0.1초다. 부하 시 시간 일부를 누적하지 않는 기존 한계는 남아 있으며, 이것을 실제 시간 기반 정산의 안전성으로 주장하지 않는다. `LocalDroppedSeconds`는 큐 상한 초과 계측이며 프레임 시간 상한에서 제외된 시간 전체까지 집계하는 값은 아니다.

상태 발행은 기본 20ms, 밀릴 때 40ms다. 발행 간격과 실제 고정 스텝을 구분한다. 맵은 변경될 때만 발행하고 계정 메타데이터는 매 스냅샷마다 복사하지 않는다. 기존 원격 모드의 160ms 표시 지연은 유지하고 로컬 훈련은 40ms 보간을 사용한다. 확정 접촉 프레임을 건너뛰지 않는 기존 방어를 유지하며 원격 이동 예측은 로컬 경로에 중첩하지 않는다.

## 통신·보상·검증의 정확한 경계

| 작업 | 이번 버전 |
|---|---|
| 입장 | 기존 HTTPS start로 계정·장비/스킬 메타데이터 취득. 인터넷 필요. 재시도 시 요청 수가 1보다 클 수 있음 |
| 이동·공격·피격·AI·도약·회피 | 로컬 실행. combat tick HTTP 없음 |
| 구역/보스 진입 | 로컬 엔진 진행 조건과 Unity readyZone/readyBoss 환경 준비를 확인 |
| 장비·성장 등 명시적 계정 작업 | 기존 서버 명령. 전투를 대기시키고 메타데이터만 반영. 서버가 반환한 훈련 위치/피해로 로컬 상태를 덮어쓰지 않음 |
| 영구 전투 보상 | 기존과 동일하게 없는 훈련. 클라이언트 결과로 골드/아이템을 지급하지 않음 |
| 구역 결과 서버 검증·비정상 이동 퇴장 | **미구현**. 이번 로컬 시험판을 안티치트/구역 정산 완성본으로 취급하지 않음 |
| 앱 종료 후 중간 구역 이어하기 | 미구현. 재입장 시 새 훈련으로 시작 |
| 기존 일반 미궁 Stage Sync·성장 사냥·포커 | 해당 실행 경로 변경 없음 |

현재 훈련 엔진의 seed 111과 고정 훈련 수치를 유지한다. 신규 프로토콜을 운영 서버에 배포하지 않고 현재 입장/계정 API를 사용한다. 따라서 **서버 main 미배포 때문에 이 APK가 구버전 실시간 전투로 돌아가는 일은 없다.** APK 자체에 새 엔진 번들이 들어 있다. 단, 입장 API 장애는 입장을 막을 수 있다.

## 검증 기록

- 기존 마을길·보스·콤보·접촉·충돌·도약·착지·API 회귀 59/59 통과. 체크아웃의 부족한 npm 의존성은 기존 검증 환경 경로로 해결했으며 소스는 현재 체크아웃을 사용했다.
- 번들 검증 3/3: 일반 입력 24,089스텝으로 10구역 300처치 후 보스 승리, 맵 발행 11회. 주기별 원래 엔진 상태와 일치. readiness·pause·단발 명령·스킬 메타데이터·독립 보스 경로 검사. 신규 네이티브 이식은 아니므로 10만 네이티브 동치 검사 적용 대상이 아니다.
- TypeScript RPG 및 신규 래퍼 타입 검사 통과. CI에 번들 최신성/실행 검사를 추가했다.
- 실제 Unity 컴파일 통과. 최초 코루틴 반환문 컴파일 오류는 수정 후 재검사했다. Play 진입 뒤 프레임 카운터 증가를 확인했다.
- 실제 검 포즈 234개: 최대 차이 `7.79004438e-7m`. 기존 표시 버퍼 45회 및 접촉 프레임 지연 방어 7개 검사 통과.
- Unity 실제 UI 패널을 통한 일시정지에서 elapsed 동일. 초기 입장 재시도 포함 HTTP 3회가 전투 진행 중 증가하지 않음. 기록 당시 공격별 접촉 39/39/38, 포즈 불일치 0. 빌드 전 186처치까지 진행. 이 수치는 Editor 결과다.

- 장비 패널의 일시정지는 전투 입력만 막도록 수정했다. 패널 열린 상태에서 `items-refresh` 성공, 잘못된 명령 400 거절 후 세션 유지, 다음 조회 성공, elapsed/위치 유지 후 전투 재개를 실제 운영 API로 확인했다.

Android 최종 빌드·기기 결과는 아래 최종 부록에 기록한다. S20은 ADB에 연결되지 않아 실제 S20 성능을 주장하지 않는다. BlueStacks가 보고하는 모델/GPU 이름은 실제 전화기 검증을 뜻하지 않는다.
