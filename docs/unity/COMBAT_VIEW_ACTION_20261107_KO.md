# 횡스크롤·쿼터뷰 액션 표현 — 2026-11-07.4

기존 실제 프로젝트 `G:/new_project/IslandGame`, Unity 6000.0.62f1 / URP 17.0.4와 승인된 수정 Nilo 룩을 확장했다. 서버·호스팅·전투 권한은 기존 Render Testplace에 유지한다. 신규 파이프라인 전환은 없다. 원격 최소 Unity 폴더에 로컬 프로젝트 전체를 덮어쓰지 않았다.

변경 소스는 [2026-11-07-view-action](client-source-snapshot/2026-11-07-view-action)에 있다. **해당 폴더는 변경 파일만 담은 참고 스냅샷이며 독립 프로젝트가 아니다.** 현재 실제 프로젝트의 후속 수정과 대조한 후 필요한 파일만 반영해야 한다. 기존 모델·애니메이션 33개 원본 해시를 보존했다. 이전 숲 전체맵 검토 씬도 유지한다.

## 전투 규칙과 보스 간격

- 이동 차단 Body, 피해 대상 Hurtbox, 실제 손·팔/검의 Hitbox는 구분한다. 기존 서버 보스·나무·경계 충돌을 유지하고 클라이언트 대시·슬라이드·점프·넉백 예측에도 최대 6 core 단위의 분할 이동 검사를 적용했다. 겹침 보정도 경계·장애물을 확인한다.
- 보스 훅은 기존 실제 본 궤적의 활성 구간, 회피 무적, 높이, 타격 번호별 중복 방지 규칙을 유지한다. 플레이어 기본 공격은 원본 검 궤적을 오프라인으로 추출해 서버에서도 캡슐 접촉을 검사한다. 기본 공격 1의 뷰별 포즈를 구현하고, 기존 1/2/3 순환에 필요한 세 검 궤적을 함께 보존했다.
- 기본 공격 공통 지속 시간 0.55초, 유효 진행도 0.32–0.58. 준비·회수에는 피해를 주지 않는다. 실제 검 도달에 맞춰 자동 접근 거리를 보스 185 / 슬라임 95 core로 조정했다. 두 뷰 모두 같은 값이다.
- 공격 정의 ID, 실행 attackId, 시작 시각, 지속 시간, active 구간, strike, cancelFrom과 contactRevision을 전달한다. 피해 이벤트는 attackId/strike/contactAt/point를 공유한다. 뷰 전환은 서버 명령이나 피해 이벤트를 새로 만들지 않는다.
- 보스 진입 후 idle 0.9초 → 추격 최대 1.35초 → 정착 0.25초. 훅 종료 후 idle 1.25초 → 추격 1.35초 → 정착 0.30초 → throw. throw 종료 후 idle 1.60초 → 추격 1.35초 → 정착 0.30초 → 훅. 이미 사정거리 안이면 추격 시간 동안 idle을 유지한다. 훅 자체 2.2초, throw 1.65초, 경고→폭발 2초는 유지한다.

## 표시와 조작

`CombatViewPresentationProfile` 두 Resources 프리셋을 `ViewPresentationCoordinator`가 읽는다. 별도 타이머 없이 `BattleCameraController`의 실제 전환 진행도/serial을 공유한다. 재요청 시 현재 카메라와 프로필에서 이어지고, 회전 초반 25%에 측면 과장을 줄여 마지막 25%에 목표 강도로 복귀한다.

| 설정 | SideAction | QuarterAction |
| --- | ---: | ---: |
| 지정 준비·회수 포즈 유지 | 켬 | 끔 |
| 최대 실루엣 변형 | 3.5% | 0 |
| Flash 길이 / 강도 | 0.12초 / 0.60 | 0.09초 / 0.45 |
| 효과음 볼륨 | 0.16 | 0.14 |
| Shake 최대 | 0.035m | 0.018m |
| FOV Punch | 0.45° | 0.18° |
| 장식 궤적 길이 / 폭 / 불투명도 | 0.09초 / 0.10m / 0.32 | 0.045초 / 0.045m / 0.20 |

접촉 활성 구간에는 포즈 시간 재매핑·스케일 과장을 적용하지 않는다. 걷기·카메라·이동을 저프레임으로 만들지 않는다. 모델 보정과 표시 변형은 다른 Transform이며 발 보정 뒤 변형한다. 전환 시 PlayableGraph를 재생성하지 않는다. `RuntimeAnimationPlayer` 블렌드는 이동 0.12초, 공격 진입 0.045초, 접촉 0, 회피 0.03초, 피격 0.04초로 구분한다.

카메라는 기존 추적·보스 프레이밍 → 전환 → 제한된 오프셋 → 최종 플레이어/보스/경고 영역 검사 순서다. 보스 뒤의 플레이어는 원본 스킨·본을 공유하는 깊이 비교 실루엣으로 위치를 표시한다. 메시 베이크와 추가 애니메이션 그래프는 없다. 이 표시는 실제로 가린 픽셀에만 나타나며, 보스 크기·몸체 판정·좌표를 변경하지 않는다.

입력은 **월드 X/Z 기준**이다. 숲 이동은 좌우 레인, 보스 구역은 평면 이동이며 카메라 모드와 독립적이다. 스틱을 유지한 채 시점을 돌려도 방향 벡터를 회전하거나 약화시키지 않는다. HUD 오른쪽 위 시점 버튼 또는 `V`로 자동 → 횡스크롤 → 쿼터뷰 → 자동을 순환한다. 보스 구역에서 W/S·위/아래는 전후 이동, `J`는 점프다. 충돌 디버그는 `F8` 또는 세 손가락 터치다.

`CombatFeedbackRouter`는 서버 접촉 이벤트를 한 번 소비해 타깃 전용 MaterialPropertyBlock Flash, 단일 오디오 소스, 카메라 오프셋, 고정 풀 효과를 연결한다. 장식 LineRenderer는 궤적 3개 + 접촉 6개이며 판정이 없다. 전역 timeScale 변경·런타임 BakeMesh는 사용하지 않는다. 저사양 정책은 장식부터 비활성화한다. 현재 첫 범위에서는 중요 스킬 배경 Dimming을 0, DOF를 꺼 둔다. 승인된 Bloom 0.10은 유지한다. 프로필의 Dimming/DOF 필드는 후속 중요 스킬용 예약값이며 자동 후처리 조절 기능으로 보고하지 않는다.

## 검증과 한계

- 서버 전투/라우트/접촉 계약 40건 통과. Unity 공통 시간·접촉 곡선·예측 충돌·중단 전환 검사 6,457개 통과. 최대 검 좌표 오차 6.67e-8m, 보스 궤적 오차 1.23e-6m.
- Flash 격리/복원·중복 이벤트·효과 상한 검사 13개 통과. 실제 HTTP 연결 Play 시험 3,583프레임에서 몸체 최소 거리 1.622567m, 예외 0. 공격 준비/접촉/회수 전환, 스틱 유지/반전, 회피·피격·넉백, pause, 연속 전환, RTT 300ms와 지터/응답 손실, 3회 재입장을 시험했다. 재입장마다 활성 그래프 10개·앱 전체 AudioSource 4개로 유지됐다.
- 비교 영상 4개는 실제 Unity Play와 격리된 HTTP 서버로 촬영했다. SideAction, QuarterAction, AttackTransitions, HitboxHurtbox 각각 약 12초다. 가변 캡처 시각을 MP4에 보존했으며 **영상 FPS는 성능 측정 결과가 아니다**. 실제 화면의 가림과 디버그 표시를 확인했다. 자동 입력 시험이며 사람의 조작감·재미·최종 미술 승인을 대신하지 않는다.
- 지연된 서버 접촉은 원래 contactAt을 유지한다. 기존 예측 시계를 유지하므로 이벤트 도착이 늦으면 짧은 Flash 일부가 이미 지난 상태일 수 있다. 0.45초보다 오래된 효과는 재생하지 않는다. 네트워크 지연 자체가 제거됐거나 모든 지연에서 음향·영상이 완벽히 동시라고 주장하지 않는다. 소리는 소스·이벤트 라우팅을 검사했으며 청음은 미검증이다.
- Android 실기 연결 없음. 아래 측정은 Android 빌드 타깃의 Unity Editor 결과이며 실기 CPU/GPU·발열·지속 플레이는 **UNAVAILABLE**이다. 사용자가 APK로 기기 시험 후 보완한다.
- 별도 TLA+/Lean 모델은 생성하지 않았다. 이번 범위는 실제 서버 접촉 테스트와 Unity 시간·상태·본 좌표 대조 및 지연/재입장 실행 시험으로 검증했다.

성능 수치, APK 검증, 배포 리비전과 회귀 결과는 같은 폴더의 Evidence 및 테스트 릴리스에 첨부한다. 측정은 동일 시드 111, RTT 150ms, 25초 워밍업 후 60초, GameView 1080×2340과 진단용 추가 URP 렌더 1080×1170을 사용한다. draw/SetPass에는 추가 진단 렌더와 Editor 부하가 들어가므로 Android 단일 카메라 비용으로 해석하지 않는다. 보스 간격·접촉 접근 거리 변화로 가시 오브젝트 수가 달라질 수 있다.
