# Boss Fight Framework 검토와 이번 어댑터 경계

사용자 제공 10보스 PDF의 설계(보스별 패턴·페이즈)를 현재 횡스크롤 Unity 테스트에 적용한다.
PDF의 기획을 바르디안 원본 보스 AI 복원 결과로 표시하지 않는다.

## 확인한 외부 코드

- 저장소: https://github.com/HadrienBoyer/Boss-Fight-Framework
- 확인 기준: `master`, commit `50b694565f95282a39d0807a1cd6971e7d06b6c2`
- 패키지: `Packages/com.tappytale.boss-framework/package.json`, version `0.1.0`.
- 패키지에 명시된 최소 Unity는 `6000.0`. PDF 표지의 `6000.4+`와 다르다.
  이것은 현재 프로젝트에서 해당 패키지의 컴파일을 검증했다는 뜻이 아니다.
- README는 일반 템플릿 상태이므로 설치 설명을 그대로 프로젝트 지침으로 쓰지 않았다.

| 파일 | 확인한 구조 | 적용 방향 |
|---|---|---|
|Runtime/Data/BossDefinition.cs|ID·표시명·최대HP·페이즈 데이터 분리|10보스 카탈로그와 런타임 상태를 분리|
|Runtime/Phases/BossPhaseController.cs|정규화HP 임계치로 페이즈 전환|보스별 임계치 및 명시적 전환 처리|
|Runtime/Attacks/BossAttackScheduler.cs|실행 중 타임라인 제외, 쿨다운·거리 조건, 순환 선택|한 번에 한 주 패턴, 공격별 준비/활성/복귀와 쿨다운|

이번 프로토타입은 외부 패키지를 manifest에 추가하지 않는다. 기존 Spine4.2/Unity6000.0 클라이언트와
새 테스트 카탈로그 위에 독립 어댑터를 작성한다. 외부 소스를 통째로 포함하거나 패키지 설치 완료로 보고하지 않는다.
외부 구조를 참고하되 별도 테스트 구현이며, BossDirector/SetDefinition API에 직접 연결됐다고 주장하지 않는다.

## 테스트 전투와 운영 전투

- 보스 선택·패턴 실험은 Unity의 로컬 샌드박스다.
- 웹/Node 전투와 계정 지갑·보상 정산은 변경하지 않는다.
- PDF의 드랍표는 기획 참조이며 온라인 보상으로 지급하지 않는다.
- 소환/분신은 적 공격 패턴이다. 플레이어 소환·토템 빌드를 새로 추가하는 작업이 아니다.
- 이동은 원본 맵의 길이축을 이용한 좌우 이동이다. 원형 포위·원뿔·비행·잠항은 회피 가능한 측면 패턴으로 조정한다.
- 새 HP 페이즈는 PDF 기반 새 보스 기획이다. 바르디안 원본 모든 보스가 같은 HP 임계치를 사용한다는 뜻이 아니다.

## 문서 모순 처리 원칙

- B03 PDF에 `Phase2 HP<=66%`와 본문 `HP<=50%`가 동시에 존재한다. 시험 구현은 본문50%를 우선한다.
- B08는 HP와 잔여 드론 수 조건이 섞여 있다. 개별 생명력을 가진5개체의 잔여 수로 진행하고 모두 처치해야 승리하도록 한다.
- PDF의 원거리6~20m를 화면 픽셀6~20 또는 웹 환산값과 혼용하지 않는다. 실제 카탈로그의 단위·어댑터를 기록한다.
- 전체 전장 공격은 무조건 피격이 아니라 안전 구역·준비 시간·점프/슬라이드 등의 대응 수단을 명시한다.

이 검토는 문서·소스 확인이며 실제 외부 프레임워크의 Unity Editor 실행 검증이 아니다.
