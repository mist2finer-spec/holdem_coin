# 역할 간 전달

기록 원본은 `mist2finer-spec/holdem_coin`의 GitHub Issues다. 채팅/로컬 메모/CURRENT는 작업 원장을 대신하지 않는다. 수신 역할 하나당 Issue 하나를 만들고 번호를 연결한다. Tier 전체의 승인 체인을 만들지 않는다.

## 보내기

1. [작업 예제](examples/task.json)를 복사해 목표·범위·발신/수신/검수 역할·대상 branch/전체 SHA·경로 최대 5개·기대 산출물·수용 기준을 쓴다.
2. 일반 작업은 관찰/추론/미확인과 출처·버전을 공유 요약에 구분한다. **역분석은 로컬 전용**이므로 상세 내용은 로컬 인계 파일에 두고 GitHub에는 절대 경로·진입 파일·식별정보·확인 상태만 담은 위치 인덱스를 보낸다. [로컬 인덱스 예제](examples/reverse-reference.json)를 참고한다.
3. `node scripts/agents/tasks.mjs init TASK.json`으로 Issue 제목/본문을 만든다. 연결된 GitHub 도구로 발행하거나 `create TASK.json`을 쓴다.
4. 새 요청은 OPEN이다. 수신자의 CLAIM이 기록되기 전까지 인수되었다고 보고하지 않는다. 발신 역할의 수신함에도 미완료 요청이 보인다.

## 받기·작업·검수

- `context.mjs <role>`의 수신함에서 선택한 번호만 `tasks.mjs show NUMBER`로 연다.
- 목표/branch/SHA를 확인하고 고유 실행 ID로 CLAIM한다. 재조회에서 owner/version을 확인한 뒤 작업한다. 같은 작업의 동시 CLAIM은 먼저 유효한 댓글만 인정한다.
- 종료 전 CHECKPOINT에 마지막 결과·다음 한 단계·미확인 항목을 남긴다. 막히면 BLOCK과 해제 조건을 남긴다. 새 세션은 기존 실행이 끝났는지 확인 후 동일 실행 ID로 이어가거나 RELEASE 후 새 ID로 인수한다.
- 제출은 커밋된 결과 파일의 전체 SHA·SHA-256·검증/미검증을 묶은 DELIVER다. 지정 검수 역할의 다른 실행자가 파일을 읽고 기준별 결과를 ACCEPT/REQUEST_CHANGES로 남긴다.
- 역분석의 커밋 산출물은 위치 인덱스뿐이다. 수신·검수자는 G:의 실제 자료와 해시를 확인하고 결과를 인계에 남긴다. CI의 인덱스 확인은 로컬 자료 확인을 대신하지 않는다. 접근 불가는 BLOCK/UNAVAILABLE이며 자료 업로드로 해결하지 않는다.
- 역할 이름을 바꾸는 것만으로 독립 검수가 되지는 않는다. 별도 검수가 수행되지 않았으면 DELIVERED로 남긴다. 도구의 구조 검사는 미술·플레이·사용자 승인을 대신하지 않는다.
- 계약/에셋 인터페이스 변경은 영향받는 역할마다 후속 Issue를 만들고 `depends_on`에 선행 번호를 넣는다. 선행 결과가 재개/수정되면 기존 검수 영수증은 더 이상 의존 근거가 아니다.
- 공유 파일/작업본은 한 작성자가 소유한다. 여러 Issue의 같은 파일 변경은 tech-director가 순서/작성자를 배정한다. 자동 잠금은 Issue 단위이며 파일 잠금이 아니다.

실행 명령·상태·오류 복구·연결 도구 사용은 [PROTOCOL](PROTOCOL.md). 준비만 요청된 작업은 조회와 준비 결과까지만 수행하며, 인계가 구현·생성·배포 허가를 추가하지 않는다.
