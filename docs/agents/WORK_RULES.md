# 조건부 작업 규칙

공통 보호 규칙은 [AGENTS](../../AGENTS.md). 아래에서 현재 작업에 필요한 절만 읽는다.

## 구현·검토

구현 전에 사용자 목표, 수정 파일, 핵심 로직, 금지 사항을 짧게 제시한다. 이미 요청된 구현 범위는 진행하고, 준비/분석 요청에서는 코드를 수정하지 않는다. 에이전트 코드와 미술 결과는 초안이며 자동 검사와 사용자 미술 승인은 다르다. 원본 자산·기존 미커밋을 덮어쓰지 않는다.

## 검사 선택

| 단계 | 적용 | 확인 |
| --- | --- | --- |
| P0 | 문서·UI·스프라이트·JSON | diff/링크/경로·스키마·좌표, 관련 검증 도구 |
| P1 | 홀덤·전투·스킬 수식·공유 코어 | P0 + 해당 도메인 통합/헤드리스 봇 |
| Full | 릴리즈 또는 명시 요청 | 전체 회귀 |

실제 checkout의 `package.json`에서 명령을 확인한다. 대표 진입은 `validate:holdem`, `test:poker:profiles`, `check:rpg`, 필요한 `test:rpg:*`. 없는 검사/도구·실행 실패·시간초과는 UNAVAILABLE/FAIL로 구분한다. 문서만 바꾸면 Unity import/Play/전체 회귀는 기본 실행하지 않는다.

홀덤 20핸드/전투 봇은 실제 플레이어에게 허용된 입력·액션으로 검사하고 시간·체력·칩 보존 등 관련 결과를 기록한다. Windows에서는 기존 Unix 환경변수 문법에 주의하고 동일 검사 파일을 실행했는지 명시한다.

## 성능·네이티브 포팅

같은 시드·부하로 함수/프레임 비용을 먼저 측정한다(60FPS 목표 16.7ms). TS/C#을 Rust/C++로 포팅할 때는 동일 시드·입력으로 최소 10만 건, 위험에 따라 60만 건 이상 대조하고 불일치 0건 여부를 기록한다.

## 아트 반복·외부 자료

원본과 각 시안을 별도 보관한다. 외곽선 단절·잡티·명도 역전 등 정량 실패를 먼저 확인하고 사용자 정성 평가를 구분한다. 2~3회 연속 개선이 없으면 비교본과 남은 문제를 제시한다.

외부 코드/대형 자료는 통째로 컨텍스트에 넣지 않는다. 필요한 경우 핵심 폴더만 `.ai_refs/`에 격리하고 요약/출처/버전을 기록한다. 대량 바이너리 전송 전에 대상 브랜치·파일·인증을 확인한다. Git CLI 인증 실패를 파일별 Base64 업로드로 우회하지 않는다.

## 형식 검증 — 조건부

동시성·취소·재시작·중복 실행·재현 어려운 핵심 오류·상태/프로토콜 계약 변경 중 기존 검사로 부족하고 검증 실익이 있을 때만 선택한다. UI/문서/단순 스타일은 제외한다.

필요하면 기존 [.agents/skills/formal-verify/SKILL.md](../../.agents/skills/formal-verify/SKILL.md)와 [검증 원장](../verification/README.md)을 읽는다. 순서/상태 경합은 TLA+/TLC, 수학적 불변 조건은 Lean 4를 먼저 고려한다. 코드 대응·가정·경계·결과를 기록하고 신규 핵심 모델은 가능한 오류 주입으로 검출력을 확인한다. 반례는 실제 코드에서 재현한다.

READY/설치/smoke test/미완성 증명을 검증 성공으로 보고하지 않는다. 규칙을 약화하거나 기존 방어 코드를 지우지 않는다. 고정 버전은 `scripts/formal-verify-source.json`; 외부 GPL 코드를 게임에 복사하지 않는다. `formal:setup`/`formal:doctor`는 도구 준비/가능 여부만 뜻한다.

## 보고·운영

결과 상태, 코드/테스트, 화면/렌더/소리, 미검증 범위를 분리한다. 운영 상태가 요청 범위이면 배포 리비전과 소스 리비전을 대조한다. 문서 GitHub 반영은 게임 배포와 구분하고 Render 비배포 커밋은 `[skip render]`를 사용한다. 운영 배포·유료 사용·DB 파괴 작업은 역할명만으로 허가되지 않는다.
