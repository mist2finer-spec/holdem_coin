# holdem_coin 작업 규칙

## 형식 검증 자동 적용 정책

### 기본 원칙
일반 개발에서는 기존 단위·통합·회귀 테스트를 우선한다. `$formal-verify` 스킬은 기본 실행하지 않는다. 핵심 안전성을 기존 테스트로 충분히 확인하기 어렵고 실제 오류 위험이 높은 경우에만 검증 실익을 평가하여 선택적으로 사용한다.

### 실행 조건
다음 중 하나에 해당하고 실익이 충분한 경우에만 사용한다.
- 동시성, 비동기 작업, 취소, 재시작, 지연 응답, 중복 실행으로 상태 충돌이 생길 수 있는 경우.
- 반복되거나 재현하기 어려운 핵심 오류를 기존 테스트로 확인하기 어려운 경우.
- 핵심 상태 관리, 프로토콜, API 계약을 변경하면서 반드시 보존할 규칙을 검증해야 하는 경우.

### 실행 제외
UI, 문서, 단순 기능·스타일 변경, 기존 테스트만으로 충분한 수정, 비용 대비 실익이 낮은 작업, 관련 모듈을 건드렸지만 핵심 안전성에 영향이 없는 작업에는 실행하지 않는다. 경로가 일치한다는 이유만으로 실행하지 않는다.

### 검증 방법
1. 기존 모델·증명을 먼저 재사용하고 영향받는 범위만 검사한다.
2. 사건 순서·상태 충돌은 TLA+/TLC, 수학적 성질·불변 조건은 Lean 4를 먼저 검토한다. 스킬이 지원하는 다른 도구가 더 적합하면 사용한다.
3. 규칙은 요구사항, API 계약, 과거 오류, 반드시 보존해야 할 동작에서 도출한다.
4. 모델과 실제 코드의 상태·동작 대응 관계, 가정, 검사 범위와 경계를 기록한다.
5. 신규·변경 핵심 모델에는 가능한 범위에서 의도적 오류를 주입하여 실제로 검출하는지 확인한다.
6. 반례는 실제 코드에서 재현하고, 수정 후 기존 테스트와 관련 형식 검증을 다시 실행한다.

### 안전 규칙
- 실패, 미실행, 시간초과, 미완성 증명, 코드 대응 미확인을 성공으로 취급하지 않는다.
- 통과를 위해 요구사항·불변 조건을 약화하지 않는다.
- 증명만 믿고 기존 방어 코드를 제거하지 않는다.
- 제한된 모델의 성공을 프로그램 전체 안전성으로 해석하지 않는다.
- 기존 증명으로 보호하는 핵심 규칙에 영향을 주는 변경은 관련 검증을 재실행한다.
- 분석 요청에서는 사용자 승인 없이 기존 코드를 수정하지 않는다.

### 효율·보고
영향도, 실제 오류 위험, 기존 테스트의 충분성으로 실행 여부를 판단한다. 불필요한 모델 생성·중복 검사·토큰 소비를 피한다. 실행 시 결과, 범위, 가정, 코드 대응, 남은 위험을 간결하게 보고한다. 생략 시 핵심 판단 근거만 작업 보고에 기록한다. 스킬·도구 미설치나 실행 불가는 명시하며 검증 성공으로 보고하지 않는다.

### 프로젝트 연결
- 필요할 때만 `.agents/skills/formal-verify/SKILL.md`를 읽는다. 이 정책이 외부 스킬의 기본 자동 실행·검사 범위보다 우선한다.
- `npm run formal:setup`: 고정된 외부 스킬 소스를 `.tools/agent-formal-verify`에 준비한다. 게임 런타임·배포 빌드에는 포함하지 않는다.
- `npm run formal:doctor -- --tool tla` 또는 `--tool lean`: 해당 도구의 실행 가능 여부만 확인한다. READY는 모델 검증 통과를 의미하지 않는다.
- 모델과 코드 대응 기록은 `docs/verification/README.md`의 절차를 따른다. 모델이 없으면 임의로 만들거나 CI에 상시 형식 검증을 추가하지 않는다.
